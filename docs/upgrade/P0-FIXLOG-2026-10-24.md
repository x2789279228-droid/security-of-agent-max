## P0-1 Sigma 阈值语义（差一 + 聚合退化）✅

核实：确认 `_agg_payload` 只带 threshold；`SigmaThresholdAggregationJob` 硬编码
`count >= threshold` 与 5m/1m 窗口；SIG-001（op `>`, threshold 5）第 5 条即告警、
SIG-007（op `>`, threshold 1）退化为单事件告警。

修复：
- `backend/sigma_engine/engine.py`：新增 `_timeframe_ms()`（Sigma 规范：裸数字按秒）
  与 `_rule_version()`（语义指纹）；`_agg_payload` 增发
  `op / func / field / timeframe / timeframe_ms / rule_version / event_id / dst_ip`。
- `backend/kafka_producer.py::publish_sigma_hit`：白名单放行上述字段（缺省值与
  Flink 回退一致：op `>=`、timeframe_ms 0 → Flink 默认 5m）。
- `SigmaThresholdAggregationJob.java`：
  - `SigmaHit` 解析全部语义字段；
  - 新增 `RuleTimeframeWindows`（自定义 `WindowAssigner`）：窗口宽度 = 规则声明的
    timeframe，滑动步长 = timeframe/5（保持旧 5m/1m 比例），仍是事件时间窗口；
  - `ThresholdWindowFunction.thresholdMet(op, count, threshold)`：按声明 op 比较
    （`>` / `>=` / `==`），认不出/`<` 一律回退 `>=`（向"更难告警"方向回退），
    `threshold > 0` 防退化闸门保留；告警回带 op/func/field/timeframe_ms/rule_version/dst_ip。

验证：`tests/test_sigma_aggregation_action_chain.py` 新增载荷/白名单契约测试 +
进程外真执行（SIG-001 第 5 条不告警、第 6 条告警；SIG-007 第 1 条不告警、第 2 条告警；
`==` 恰好触发；未知 op 保守回退）。

## P0-2 单事件提前触发 FastPath 封禁 ✅

核实：确认 `detect_for_event` 对 pending-only 命中返回 `detected=True`；
`ingest_pipeline.detect` 不读 `requires_aggregation` 直接抬分；
FastPath `_fused_conf >= 0.7` → `allow_blocking=True`。

修复（engine → ingest → audit_triage → FastPath 四层）：
- `engine._detect_for_event_inner`：`detected` 只反映**已确证**（非聚合）命中；
  pending-only 时 `detected=False / status=partial / max_severity="" /
  action_recommend="alert"`，候选保留在 `hits/pending_aggregation` 供审计。
- `ingest_pipeline.detect`：抬分前检查 `pending_aggregation` 且 `confirmed_hits==0`
  （防御同一契约，旧引擎载荷也不复活该路径）。
- `dispatch()`（FastPath）：`_sigma_critical` 加 pending 门控；融合置信度跳过
  `requires_aggregation` 命中；pending-only 事件**永远**不进 `_strong_signal`
  → `allow_blocking=False`，只能告警/审计。
- `audit_triage._fused_confidence`：同样跳过待聚合命中。

验证：`tests/test_p0_requires_aggregation_boundary.py`（engine 行为 + detect 抬分 +
融合置信度 + FastPath 源码钉）。执行类动作现在只属于 Flink `SIGMA_AGGREGATE` 告警。

## P0-3 HTTP 网关 Kafka 模式全 503 ✅

核实：确认网关投递 wrapper（`uuid/eventId/body/...`），而
`security-events-ingest` 绑到 `security_event.schema.json`（要求顶层
eventType/severity/message/timestamp）→ `produce_raw_batch` 校验失败 →
`produced=0` → 503 not_durable；未装 jsonschema 时校验被跳过（问题被掩盖）。

修复：
- 新增 `backend/schemas/ingest_wrapper.schema.json`（顶层 uuid/eventId/type/body
  必填；body 必含网关盖章的 `eventId`），`contracts/baseline/` 同步基线副本；
- `contracts/catalog.json` 与 `backend/schemas/catalog.json`：`security-events-ingest`
  改绑 `ingest_wrapper`（security_event 保留其余 4 个 topic）；
- `schema_registry.py` 兜底映射同步；
- batch 接口与单条接口共用 `_authenticate_source()`（无效 key → 403，鉴权前置）。

验证：`tests/test_ingest_wrapper_contract.py` —— 用 `_enqueue_ingest` **真实代码路径**
构造 wrapper，断言通过 topic 契约校验、`produce_raw_batch` 全链路
`produced == len(events)`；扁平事件被 wrapper 契约拒绝（反向钉）；batch 鉴权 4 例。
`python tools/check-schema-compat.py` 门禁通过。

## P0-4 60 秒去重不是窗口去重 ✅

核实：确认 `ValidationAndDedupFunction` 只有"上一个指纹"单值状态（A,B,A 挡不住）、
指纹不含 eventId、重复事件混入 rejected。

修复（`LogValidationJob.java`）：
- `ValueState<String>` → `MapState<fingerprint, lastSeenMs>`（事件时间 60s 窗口判定，
  `abs(now-last) < 60_000`，TTL 60s 兜底清理状态）；
- 新增 `DUPLICATE_TAG` 侧输出 + `security-logs-duplicate` topic 独立 sink
  （事务前缀 `soc-logval-dup`），rejected 不再混入 DUPLICATE；
- keyBy 由 srcIp 改为 `sourceId|eventType`（同指纹必同 key，去重正确性不变，
  消除 srcIp 热键）；
- `KafkaConfig.TOPIC_DUPLICATE_LOGS` + `tools/init-kafka-topics.sh` 新 topic
  （3 分区/7 天）。

## P0-5 密钥泄露 ✅

核实：确认拒绝原因拼接 key 原值、`emitRejected` 整个 originalEvent（含 apiKey）
落 rejected、batch 未鉴权。

修复（`LogValidationJob.java` + `routers/logs.py`）：
- 认证失败原因只记 SHA-256 前 8 位指纹（`keyFingerprint`）；
- 认证**成功后立即** `setApiKey("")` —— validated 及全部下游流不再携带凭据
  （置空串而非 null，保持 JSON Schema `apiKey: string` 约束）；
- `emitRejected` / `emitDuplicate` 落盘前脱敏；JSON 解析失败导出的 rawMessage
  正则抹除 `"apiKey":"..."` 值；
- batch 鉴权见 P0-3。

## P0-6 重启重放破坏幂等 ✅

核实：确认三个作业 `OffsetsInitializer.earliest()`、提交脚本不带 `-s`、
compose 无 externalized retention、缺 eventId 时 `UUID.randomUUID()`。

修复：
- `docker-compose.yml` FLINK_PROPERTIES 增加
  `execution.checkpointing.externalized-checkpoint-retention: RETAIN_ON_CANCELLATION`
  与 `num-retained: 3`；
- `submit-jobs.sh` 支持 `FLINK_RESTORE_SAVEPOINT=<路径>`（`flink run -s`，
  可选 `FLINK_ALLOW_NON_RESTORED_STATE=1`）；`auto-submit.sh` 守护透传
  （compose 的 `flink-job-submitter` 增加环境变量透传）；earliest 明确为
  **首次启动**兜底，恢复场景 offset 来自恢复点（三个作业源码注释同步）；
- `LogValidationJob`：缺失 eventId 用内容指纹生成**确定性 ID**
  （`auto-<sha256(source|type|srcIp|message|timestamp)[:16]>`），重放同一条
  Kafka 记录得到同一 ID，下游幂等键不再失效。

## P0-7 null srcIp 的 keyBy 风险 ✅

核实：确认校验允许 srcIp 为空，`AnomalyDetectionJob` 5 处 `keyBy(SecurityEvent::getSrcIp)`
（评分 + CEP×4）对 null key 哈希会 NPE。

修复：
- `LogValidationJob.normalizeEventEnhanced`：srcIp null/空 → 归一 `"unknown"`，
  并打 `rawData._srcIpMissing=true`（区分"真 unknown 源"与"缺源事件"）；
- `AnomalyDetectionJob`：新增 `srcKey()` 空值安全键函数，评分/部分匹配/CEP 三模式
  全部改用（纵深防御，旧数据/旁路数据也不踩 null）。

## P0-8 秒级时间戳先拒后修 ✅

核实：确认 `validateSchemaEnhanced`（毫秒范围校验）先于 `normalizeEventEnhanced`
（秒→毫秒修正）执行，秒级时间戳必被拒。

修复（`LogValidationJob.JsonParseProcessFunction`）：
- 新增 `normalizeTimestamp(event, ctx)` **在 schema 校验前**执行：秒（<1e10）×1000、
  微秒（≥1e14）÷1000、纳秒（≥1e17）÷1e6；
- 归一后仍非法时回退 Kafka record timestamp（`ctx.timestamp()`，KafkaSource 无
  自定义 assigner 时记录时间即 record ts），再不行回退处理时间；
  所有回退打 `rawData._eventTimeMissing=true`，另打 `_tsNormalized=true`；
- `normalizeEventEnhanced` 中的迟到秒→毫秒修正移除（避免双重归一）。
