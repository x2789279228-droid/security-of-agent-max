## 3. 标定回填（Wave 2-2 闭环）

- **`kafka_consumption_eps`（实测稳态单 worker 消费容量）= 8**（本轮 8.4-8.6 实测取整保守值）。
  部署该规模栈时设置 `SHARED_MEMORY_KAFKA_CONSUMPTION_EPS=8` 激活 lag 背压信号
  （阈值条数 = 8 × `kafka_lag_allowed_backlog_s`，默认 60s → 480 条容忍窗）。
  config.py 注释已同步该标定口径；**默认仍为 0（未标定不启用）**——不同规则库规模/机器需重新标定。
- 多 worker 线性扩展证据（2.08× + CPU 配额打满）支持按 worker 数近似线性估算容量。

## 4. 已知断点（如实）

1. LLM 供应商 429 风暴：审计车道跌至 1-2 eps（现场数据见 LLM-RESILIENCE §4）；
   2w 吞吐测量的首轮 0.67× 即其污染（配对复测 2.08× 澄清）。
2. 直灌 Kafka 绕网关的载荷会被 schema 校验拒收（网关即 schema 闸门，A3 实验 C）。
3. 3 条超长 IN 规则触发 SQLite 表达式深度上限（B2 已登记）。
4. 全 profile（3 broker）的 broker-kill 注入未在本机执行（lite 单 broker 即全灭，
   本轮以 4s 停机窗的 lite 变体替代：缓冲接受+恢复零丢失）；full profile 留部署环境。
