## 0. 三条执行原则

### 原则一：代码默认值改为安全值，演示能力用 env 显式开启

项目已有现成机制：`.env.demo.example` 就是"B 类能力一键开启"的覆盖层。因此**不需要在"安全"和"演示"之间二选一**：

| 配置项 | 当前代码默认 | 改为 | 演示时 |
|---|---|---|---|
| `execution_mode` | `live` ⚠️ | **`dry_run`** | `.env.demo.example` 加 `SHARED_MEMORY_EXECUTION_MODE=live` |
| `allow_self_registration` | 无（永远开）⚠️ | **`False`** | `.env.demo.example` 加 `SHARED_MEMORY_ALLOW_SELF_REGISTRATION=true` |
| `control_hmac_key` | `""`→回退公开常量 ⚠️ | **缺失即启动失败** | `.env` 加 `SHARED_MEMORY_CONTROL_HMAC_KEY`（独立随机值） |
| `llm_budget_unlimited` | `True` ⚠️ | **`False` + 真实额度** | `.env.demo.example` 按需放开 |

> **注意**：`.env.example` 有 160+ 个键，但**没有** `EXECUTION_MODE` / `CONTROL_HMAC_KEY`。这意味着当前演示环境一直在用最危险的两个代码默认值运行，且无人察觉 —— 这本身就是需要修的文档缺陷。

### 原则二：身份一律来自 token，不接受请求体传入

批次 1 是后续多个批次的上游。本项目最系统性的问题不是某个守卫写错了，而是**守卫内部实现正确、调用它的端点却把身份字段交给了客户端**。因此批次 1 单独成批，先把"身份真值来源"这一件事在全局统一，避免后面每个补丁都各写一遍。

### 原则三：每个批次必须自带回归测试，且测试不得固化脆弱行为

**已确认会因加固而失败的现有测试**（必须同步修改，不能靠删测试绕过）：

| 测试引用 | 数量 | 影响的批次 |
|---|---|---|
| `settings.execution_mode` | 52 处 | 批次 3（多为显式设 `mock`，预期不受影响，需跑一遍确认） |
| `jwt_secret` | 38 处 | 批次 3（HMAC 改为回退到 jwt_secret 后应仍通过，**这是刻意的兼容路径**） |
| `admin_password` | 36 处 | 批次 1 |
| `logs/ingest` | 8 处 | 批次 1（需补 `X-API-Key`） |
| `guard/call` | 2 处 | 批次 1（需改为断言服务端身份） |
| `rag/documents` | 1 处 | 批次 2 |

> **两个必须改写的测试**（它们当前把缺陷当成了正确行为）：
> - `tests/test_control_plane_security.py` —— fixture 只固定 TTL、不固定 HMAC 密钥，所以**无论是否配置密钥都通过**。必须改为断言"密钥缺失时抛异常"。
> - `tests/test_mcp_guard.py:8-9` —— 辅助函数 `_req(role="admin")` **硬编码特权角色**，因此单元测试全绿而 HTTP 边界是敞开的。必须补一条"viewer token 调受限工具返回 403"的端到端断言。

SEVERITY_ALIASES = {"informational": "info", "crit": "critical", "medium-high": "high"}

def _passes_thresholds(self, confidence: float, severity: str) -> bool:
    if confidence < self.min_confidence:
        return False
    sev = str(severity or "").strip().lower()
    sev = SEVERITY_ALIASES.get(sev, sev)
    if sev not in severity_order:

### 7.1 PQ pop 改原子（P0-13）— 最高优先

-- 一次性 Lua 脚本：ZPOPMIN + GET + DEL 原子化，payload 缺失时放回而非丢弃
local m = redis.call('ZPOPMIN', KEYS[1], 1)
if m[1] then
  local p = redis.call('GET', 'pq:p:'..m[1])
  if p then redis.call('DEL', 'pq:p:'..m[1])

end
return ''

## 15. 建议执行方式

**按批次串行推进，每批次一个 PR + 一次完整回归**，不建议多批次并行改同一区域（批次 1/2/5 都触及 `routers/`，批次 5/7 都触及 `retriever.py`）。

1. 批次 0 的密钥轮换 + 分发净化（**已泄露，必须先做**）
2. 提交 1.1 CORS 位置（一行，修复所有人正在遇到的登出失败）
3. 批次 2 的 SQL 注入（独立、低风险、影响面明确）

这三项合在一起风险极低、收益立即可见，适合作为建立整改节奏的第一个里程碑。
