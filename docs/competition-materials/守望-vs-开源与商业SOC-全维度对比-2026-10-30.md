# 守望 vs GitHub 开源 SOC vs 商业 SOC —— 全维度对比（2026-10-30）

> 数字口径说明：守望侧全部取自仓库内实测文档（README / `backend/capabilities.yaml` / `docs/benchmark/PERF-2026-10-26.md`）；外部产品取自 2026-10-30 的公开调研（厂商官网、Gartner、IDC、GitHub），来源清单见文末。

## 0. 结论先行

守望的坐标不是"另一个 Wazuh"，也不是"便宜的 Sentinel"，而是：

> **用开源 SOC 不具备的"多智能体编排 + Agent 治理 + 检测自进化"，去落地商业 SOC 在 2025–2026 年才集体转向的"Agentic SOC / AI Analyst"理念。**

- **理念层**：与 Palo Alto AgentiX、Microsoft Sentinel Copilot Agents、深信服安全GPT 同频，且部分更激进（CAD 独立监督、工具行为 UEBA-for-AI、红蓝自博弈检测进化在业界均无直接产品化对等）。
- **工程层**：是诚实标注的原型——单进程检测 ≈23.5 eps（商业产品为每日数十亿事件级）、Sigma 规则 159 条（Wazuh 约 3000、XSIAM 宣称 10000+）、18 项能力中仅 4 项 verified。

一句话总结：**检测内容广度、性能规模、连接器生态三个维度落后业界 1–2 个数量级；Agent 化架构、Agent 安全治理、检测自进化、工程透明度四个维度对齐或领先业界最前沿。**

## 2. 全维度对比

### 2.1 平台形态与成熟度

| | 守望 | GitHub 开源 | 国际商业 | 国内商业 |
|---|---|---|---|---|
| 定位 | 多智能体 SOC 一体化平台（接入→检测→LLM 审计→响应→复盘闭环） | 分工拼装：SIEM(Wazuh/SO)+案例(TheHive/IRIS)+情报(MISP/OpenCTI)+SOAR(Shuffle/Cortex)+取证(Velociraptor) | 一体化 SaaS 平台，兼做数据湖 | 大数据平台+MSS 托管运营 |

## 3. 守望领先或对齐业界前沿的六个点

1. **被监督的多智能体**：四层流水线 + CAD 独立监督（熔断器+穿透验证）+ 反幻觉三闸门（grounding/faithfulness/veto）。业界 Agentic SOC（AgentiX、Copilot Agents、安全GPT）普遍缺"独立监督 Agent"这一层——守望的答案直接回应"企业不敢让 AI 自动处置"这一采用障碍。
2. **Agent 行为治理（UEBA-for-AI）**：MCP Guard 4 层 + 工具行为签名 + 审批队列。开源完全空白；Exabeam/Securonix 2026 年才推同类（且方向是监控员工用 AI，不是治理 SOC 自身 AI）。
3. **检测自进化闭环**：红蓝自博弈 + 反馈回灌 + 学习闭环，业界无直接产品化对等；把"规则僵化"从静态规则分发的行业默认态变成可自动对抗进化。
4. **一体化 vs 开源拼装**：开源自建 SOC 要 6–8 个系统胶水粘合，守望单仓库原生闭环（接入→检测→审计→响应→复盘→学习），且 76% 告警可无 LLM 规则收口（有实测侧证）。
5. **可复现评测文化**：CSIC-2010 全量回放 + 分层消融 + 对抗保持率（对抗编码攻击保持率 1.0）+ 吞吐压测，全部保留整改前后数字——四阵营中透明度最高。
6. **工程诚实度即护城河**：capabilities.yaml 登记制、休眠模块守卫测试（代码存在但没接线就自动转红）、PERF 报告自曝 8 个阻断项与瓶颈定位——这种"不假装能跑"在竞赛与评审场景是稀缺品。

## 4. 客观差距（建议答辩时主动承认）

1. **吞吐**：单进程检测 ≈23.5 eps，与商业产品（日数十亿事件）差 2–3 个数量级；瓶颈已定位、修法已有（PERF-OPT-PLAN），但当前数字就是原型级。
2. **检测内容库**：159 条 Sigma（其中 130 条 SigmaHQ 社区规则还在影子模式）vs Wazuh 约 3000 条、XSIAM 宣称 10,000+。
3. **异常检测实战可用性**：真实流量面 100% inconclusive（能力页如实标注 experimental），UEBA 与 Exabeam/Securonix 十年积累差距明显。
4. **连接器生态**：XSOAR/Shuffle 有 1000+ 集成；守望执行通道为 SSH/API/邮件三类 + 自家适配器。
5. **部署形态**：单机 docker compose（lite/full profile）为主，Flink HA 仅叠加文件；无多租户、无 SLA 体系。
6. **未完成项**：0day 沙箱 disabled、响应回滚对 iptables 规则失效（已披露待修）、7 个模块曾长期未接线（2026-10-27 刚收口 2 个）。
7. **无市场验证与认证**：无等保/SOC2/ISO，无真实客户运行时长；对比 Wazuh 全球社区与商业厂商十年客户积累。
8. **LLM 依赖**：审计 LLM 通道依赖外部 API（默认 mimo-v2.5），主备 fallback 已有但供应商故障剖面未压测。

## 5. 定位结论与使用建议

- **一句话定位**：守望 = 开源全栈的骨架 + 商业 Agentic SOC 的理念 + 学术前沿的能力（自博弈/因果推断/Agent 治理）的研究型原型。
- **对标开源**：不与 Wazuh 拼规则数量和端点管理规模（必输），主打"开源栈没有的一体闭环与 AI 治理"——开源阵营连统一的 Agent 编排/权限/审计框架都还没有，这正是守望的开源生态位。
- **对标国际商业**：承认性能与成熟度差距，强调理念同频且更透明——2025 下半年起 Sentinel/Splunk/XSIAM/CrowdStrike/Google 集体转向 Agentic SOC，验证了守望的路线判断；守望的差异化是"被监督的 AI"（CAD/veto/白名单/dry_run 默认）。
- **对标国内与赛题方（深信服）**：SIP 走"全流量分析 + 联动处置 + MSS 人天"路线，安全GPT 是其智能化方向；守望恰好是"智能体自动化运营"路线的完整实验场。材料中可引用深信服自身"国家级测试智能体自动化分析响应第一"的叙事互证赛道正确性，再指出守望补上了行业共性短板（厂商封闭生态、规则更新依赖厂商、降噪数字缺独立验证 → 守望全开源 + 公开数据集评测）。
- **性能答辩口径**：130.8 eps 是 2CPU 容器的接入峰值实测、零丢失；检测瓶颈在 Python 单进程（42.46ms/事件），已定位修法；Kafka/Flink 架构层尚有余量——把话题从"数字小"引导到"瓶颈定位清晰、架构可扩展"。
